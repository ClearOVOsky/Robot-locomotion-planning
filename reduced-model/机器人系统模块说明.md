# 机器人系统整体架构：模块说明

核心流程：**采集数据 → 预处理 → 环境感知与自身状态估计 → 更新世界模型 → 任务决策 → 运动规划 → 反馈控制 → 执行器动作 → 再次感知**。

这是一套通用的功能划分，不代表每个机器人都需要独立部署所有模块。感知、估计、规划和控制通常以不同频率并行运行，通过反馈不断修正动作。

| 编号 | 模块 | 具体功能 |
|---|---|---|
| 01 | 传感器与驱动 | 从相机、雷达、IMU、编码器和力传感器等采集环境与本体数据，并提供统一读取接口。 |
| 02 | 数据预处理 | 对齐时间戳，应用传感器标定参数，去除噪声并转换坐标系，使不同数据能够共同使用。 |
| 03 | 环境感知 | 识别和跟踪物体、人员、障碍物，估计其位置、形状与运动，回答“周围有什么”。 |
| 04 | 状态估计与定位 | 融合传感器信息，估计机器人位置、朝向、速度、关节状态及不确定性，回答“我在哪里、如何运动”。 |
| 05 | 世界模型与地图 | 汇总感知与定位结果，维护障碍物、可通行区域、物体关系等可查询的场景表示，供规划和决策使用。 |
| 06 | 任务输入与人机交互 | 接收目标、指令和约束，向用户显示状态，并支持遥操作与人工接管。 |
| 07 | 任务规划与行为决策 | 将目标分解为子任务，选择导航、抓取等技能，决定执行顺序，并在失败时重试、切换策略或求助。 |
| 08 | 运动规划 | 根据子目标、当前状态和环境约束，生成避障且满足机构、速度和加速度限制的路径及带时间信息的轨迹。 |
| 09 | 反馈控制 | 比较期望轨迹与实际运动状态，持续计算和修正位置、速度或力矩指令，使机器人跟随目标运动。 |
| 10 | 执行器与底层驱动 | 将控制指令转化为电机、关节、夹爪或制动器的物理动作；驱动器通常还包含更快的内部控制环。 |
| 11 | 安全与故障管理 | 监测碰撞风险、限位、通信异常和设备故障，实施限速、停止、故障恢复或急停联锁。硬件急停应有直接作用于驱动的通路。 |
| 12 | 系统基础设施 | 提供模块通信、统一时钟与坐标系、算力调度、参数配置，以及电源和热管理，保障系统协同运行。 |
| 13 | 开发与运维工具 | 通过仿真、标定、日志回放、测试、部署和运行监控，支持开发验证与问题定位。 |

## 如何阅读架构图

- 蓝色：把原始测量转为可用的环境信息。
- 紫色：形成机器人自身与外部世界的状态表示。
- 黄色：接收任务，决定做什么，并规划怎么动。
- 绿色：控制与执行，让实际运动接近期望运动。
- 红色：安全监督与故障处理；图中只画出代表性的监督接口。
- 灰色底座：支撑整个系统，省略逐一连线。
- 实线表示主要数据或指令流；虚线表示反馈或监督。连线是关键关系示意，不是完整接口清单。

## 两个必须理解的闭环

1. **环境与任务闭环**：动作改变环境或本体状态，传感器重新观测，系统更新场景并继续决策。例如前方突然有人，机器人更新障碍物信息并重新规划。
2. **运动控制闭环**：控制器比较期望运动与实际状态并纠偏。例如希望关节转到某角度，但尚未到达，控制器继续调整输出。

## 一个例子：拿起桌上的杯子

相机采集画面 → 预处理 → 感知识别杯子与桌面 → 状态估计提供机械臂当前姿态 → 世界模型记录杯子位置与障碍物 → 决策分解为“接近、抓取、抬起” → 规划生成无碰撞关节轨迹 → 控制器跟踪轨迹 → 电机和夹爪执行 → 视觉或力觉确认抓取结果，失败则重新决策。

## 适用边界

固定机械臂可以不做移动底盘定位；移动机器人通常更重视导航与建图；人形机器人还需要平衡、接触状态估计和全身控制，可细分在上述模块中。SLAM（同时定位与建图）可以联合实现部分状态估计与地图功能。学习模型可以用于感知、决策、规划或控制；“世界模型”在这里指场景表示，不一定是生成式模型，也不要求使用大语言模型。
